# Lark 终态投递：发送成功才确认，失败重放（at-least-once + 幂等键去重）

M17.5 P3 的原语义是 at-most-once：发送前先写**带终态**的 message_delivery（注释明言「reconnection won't re-send」），重试 3 次失败后跳过并推进 pushed_seq。三重叠加（终态预写 + 重试耗尽不抛错 + 无条件推游标）导致发送失败即**永久漏发终态**——backend 已完成、账本有结果，用户永远收不到。对远程控制面这是 P0。2026-09-23 修复时显式翻转该取舍。

## 决策

1. **发送前投递意图记非终态标记（`streaming`）；发送成功后才写终态确认并推进 pushed_seq。** 重放路径遇到非终态标记会重发，遇到终态标记才跳过。
2. **重试耗尽抛错**，断开该会话的 SSE 连接，重连后从游标重放该条，以**同一** lark-cli idempotency key（`conversationId:messageId:seq`）重发，Lark 侧去重使实际送达过的重放为 no-op。「已发出、未确认」的崩溃窗口同样由该幂等键兜住。
3. **宁可重放，不可跳过。** 游标推过一条未投递的终态是被禁止的；断流重连是恢复手段，不是故障。
4. **tool 行默认不投递**：原始工具输出不进群聊（摘要归 Run 卡片，ADR 0031）。

## 后果

- 投递语义变为 at-least-once，**依赖 lark-cli `--idempotency-key` 的真实去重能力**；更换发送通道必须保留等价幂等语义。
- 抛错会掐断单会话的 SSE 连接（5 秒后重连），同一 watcher 后续条目延迟一个重连周期——用延迟换不丢终态，是本决策的代价。
