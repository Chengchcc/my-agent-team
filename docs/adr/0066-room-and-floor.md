# ADR 0066: 会议室与展厅 —— 房间只记人和前台，工人自己的事在它自己的页面

- 状态: Accepted（房间过滤与"Dispatched units"已实现；**下车间直接指挥**为 D4，实现中）
- 日期: 2026-11-18
- 相关: ADR 0049（前台不变量）、ADR 0050（呈现三原则）、ADR 0060 D3（署名）、ADR 0061（注意力轴）

## 背景

人给的模型（原话比术语准确）：

> 我作为老板，布置任务给前台秘书，秘书再下发给工人。一般情况下我只要听秘书汇报，汇报不会说工人过程做了什么；只有在需求不明确、工人执行碰到问题时才通知我。但我有时也会要深入一线，看看工人是怎么做的，甚至有必要直接指挥工人。

当时的实现与这个模型不符：账本是共享的，房间时间线把**工人的工具行也画在房间里**（`read`、`bun test`、`edit`…），相当于会议室里外放着车间对讲机。

人另外明确了两条通道事实：**日常对话走 Lark，沟通记录落在会议室（Web 房间页）**；展厅是单独的 Web 页面。

## 决策

### D1 房间只记人和前台

房间时间线按 `_meta.authorAgentId` 过滤：**其他 agent 说的话、跑的工具不进房间**。它们仍在账本里（可审计），只是不在这一间房的对话里出现。

派单说明（前台起草、以 user 角色落账的那条）**保留**——那是秘书自己的话。

### D2 展厅是单独的页面

从房间的派单折叠块 `Run ↗` 进入；它给出**这一次执行**的事实（授权依据、父 run、状态、验收、用量）。

因为记录与对话分处两个通道，入口链必须是通的：**Lark 卡片 → 前台 run 页 → Dispatched units（本次派了谁）→ 工人的 run 页**。最后一段是本 ADR 补的（`GET /api/agent-runs?parentRunId=…`），否则"在 Lark 里听到修好了"的人没有路下去看证据。

### D3 下班规则：只有秘书把人叫回来

工人没有任何直接对人的通道：`report(attention)` → 唤醒前台 → 前台改写成人话。这条已在 ADR 0059 D5 落地，本 ADR 只是把它写进这套比喻里。

### D4 下车间：人可以直接对工人说一句，房间里留摘要

- **入口**：工人 run 页上的一个输入框（"在这里直接对它说一句"）。
- **授权**：走的仍是 `user`（服务端设置，HTTP 入参不能自称）。这是 ADR 0049 前台不变量的**唯一显式例外**：人工输入点名工人时默认改路给前台，除非这次输入被明确标为"下车间"。
- **摘要**：这条指令同时以人的署名留一条账本记录（不点名任何人、不触发新 run），措辞"（我在 <工人> 的工位上说：…）"。秘书的下一轮从共享账本里读得到它——否则工人回来汇报"按你说的改成了 A"时，秘书不知道你说过什么。
- **不做**：不经摘要的直接指挥。上下文断成两半的代价比一次弹窗高。

## 不变量

1. 房间视图只画人和前台；工人的行只在一线可见（账本仍是共享的）。
2. 直接指挥必须留摘要；没有摘要的"下车间"不存在。
3. 授权依据仍由服务端写；HTTP 入参只能请求"这是一次下车间"，不能自称授权。

## 验收

1. ✓ 另一个 agent 的 prose 不会变成房间的一行（变异：去掉过滤 → 红）。
2. ✓ 可以按"派它的 run"列出子 run（变异：去掉过滤 → 红）。
3. 工人 run 页发一句话：工人那一轮收到的是原文，`authorization=user`；**前台的那条分支不会被触发**。
4. 同一条指令在账本里留下人的署名的摘要，且不触发新 run。
5. 普通人工输入点名工人时**仍然**改路给前台（回归，防这次例外被放宽成默认）。
