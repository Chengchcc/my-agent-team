## 产品逻辑

人面对的是**前台**——有名字、有脸（lark bot）、可以直接说话的 agent。
工人是**后台资源**——没有脸，不接受人的直接指令，只被产品派发。

Web 端呈现的是这个**团队结构**，不是一堆平级的 agent。三条原则：

1. **分区不分级**：前台和工人在视觉上分开（不同区块、不同图标），但都是一等公民——工人不是"低级 agent"，是不需要脸的专家。
2. **能力卡是工人的脸**：工人没有 lark，它的 skills/description 就是派单决策读的东西——在 UI 上要突出，在表单里要易填。
3. **人够不着的地方不露出来**：工人的 lark 配置面（schema 已互斥）、新建会话的 agent 选择器（后端已 400）、聊天成员添加的下拉——凡是人直接操作工人的入口，UI 侧也收掉。

## 呈现面

### 团队页

```
◆ 前台（人直接对话）          ← 前台卡片：飞书状态、模型、绑定
┌────┐ ┌────┐
│领班A│ │值班B│
└────┘ └────┘

◇ 工人（只接受派发）          ← 工人卡片：能力卡（skills chips）突出
┌────┐ ┌────┐ ┌────┐
│前端工│ │后端工│ │文档工│
│react│ │ api │ │写作 │
└────┘ └────┘ └────┘
```

### Agent 表单

| 配置面 | 前台 | 工人 |
|---|---|---|
| 角色（front/worker） | ✓ 初始选择 | ✓ 初始选择 |
| 名称 + **描述** | ✓ | ✓ |
| **能力卡 skills** | ✓ | ✓ 突出（这是被选中的依据） |
| 模型/harness/权限 | ✓ | ✓ |
| **飞书配置** | ✓ | 隐藏（schema 互斥 + UI 不露） |
| 环境规则 | ✓ | ✗ |

### 聊天面

- 新建会话：agent 选择器只列前台
- 成员面板：添加成员下拉过滤工人；工人成员带"工人"角标（显示它在干活但不可 @）

## 实现落点

全部是渲染层——`role`/`skills`/`description` 已在 DTO 上（A2A 语义对齐表红利）：

| 文件 | 改动 |
|---|---|
| `team/page.tsx` | 分区（fronts/workers）、工人卡片渲染 skills chips |
| `AgentForm.tsx` + `agent-form-types.ts` | role/description/skills 字段、lark 段按角色隐藏 |
| `chat/page.tsx`（新建会话） | agent 选择过滤 worker |
| `ConversationMembers.tsx` | 添加成员过滤 worker、工人角标 |
| `agent-description-card.tsx` | 渲染能力卡（description + skills） |

## 不做的事

- 不在 Web 加"手动派单"按钮——那是领班 run 里 dispatch 工具的活。
- 不在工人卡片加"发起对话"——工人没有对话入口。
- 研判闸门/事件流面板不进团队页——那是运维面（roadmap：设置页或独立面板）。
- 不做 composer 成员自动补全——现有自由文本 @ + 发送时解析已够用（后端重路由兜底）。
