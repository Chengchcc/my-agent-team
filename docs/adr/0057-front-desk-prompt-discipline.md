# ADR 0057: 前台的路由纪律（提示词层）

- 状态: Implemented
- 日期: 2026-11-17
- 相关: ADR 0054（意图维度）、ADR 0055（记忆检索）、ADR 0056（能力召回）

## 背景

golden 语料（ADR 0054 末节）量出三类可复现的模型偏差，**没有任何 schema 能拦住它们**：

1. 把 `verb` 填进一个叫 `action` 的字段（工具里根本没有这个字段）；
2. 把 `write` / `investigate` 当成 `answer`——"写份文档"被当成一句话能满足；
3. 请求里已经写明的细节被报成缺失。

第 1 类在工具层会被拒（`dispatch requires verb`），但代价是一轮往返；第 2 类根本不会被拒——它压根不派单；第 3 类会让前台反复问人已经答过的事。

这三种都不是"表格错"，是**模型对"什么算工作"的判断**。所以修在提示词，而不是再改表。

## 决策

### D1 一段固定纪律，注入给所有面向人的 agent

- 注入条件：`role !== "worker"`（含 `role` 为空的旧 agent）。
- 位置：**身份之后**（SOUL.md / USER.md 先），因为纪律是产品的约束，身份是个体的描述；个体的措辞不该覆盖约束。
- 工人不注入：它没有人可以路由，规则对它只是噪音。

### D2 三条出口，默认是"回答"

规则短而硬（约 20 行），因为它每轮都随提示词走：

```
1. ANSWER —— 一句回复就能满足（解释、确认、回忆）。大多数消息是这一类。
2. ASK    —— 是活，但缺必需细节。一次问完。
3. DISPATCH —— 是活，且规格完整。
```

配套三条对应上面的偏差：

- `verb` 是 dispatch 的**参数**，不是出口；没有 action 字段；`operate` 不是"代替派单去做"。
- 产出东西（write）或找原因（investigate）是**工作**：一句话交不出文档或根因，所以它们永远不是 ANSWER。
- 派单前查槽位：**请求已经写明的细节不算缺**，不许再问；没写明的**不许编**（问，或点名给谁）。

外加两条产品不变量：不可逆 `operate` 需要本轮人类的话；一条消息里的多个任务是多个 brief。

### D3 不注入就没有基线

`scripts/golden-intent.ts` 现在**直接引用同一段常量**（`FRONT_DESK_DISCIPLINE`），不再维护第二份提示词。基线因此是"产品提示词的基线"，不是"脚本的基线"。

## 验证

同一批 17 条可判定用例（另 3 条需要多 brief 或记忆上下文，回放里跳过），同一模型（deepseek-chat），连续三次：

```
15/17 · 12/17 · 15/17     （中位 15）
```

改动前的数字是 11/17，但那是**另一份临时提示词 + 单次运行**，与现在不可直接比较——这一点写在这里，是因为一开始我把它当成了"改进的证据"，而它只是噪声。

仍然失败的三类，都已记录：

| 用例 | 现象 | 性质 |
|---|---|---|
| `ask-investigate-thin` | 判成 answer | 第 2 类偏差（模型认为"查原因"能一句话满足） |
| `ask-operate-thin` | 已给的环境/动作仍报缺 | 第 3 类偏差（槽位识别靠模型判断） |
| `dispatch-operate-reversible` | `action` 里塞进了整句指令 | 第 1 类偏差（枚举纪律不稳） |

**结论**：这三条提示词压不住全部，属于"模型能力 + 采样方差"，需要换更强的模型或加一层校验才有质变。当前价值在于：它们现在是**可复现、可计数的**，而不是靠感觉。

## 后果

- 每个前台 run 的系统提示词多约 20 行（~150 token/轮）。可接受，但不要在这里长草：加规则前先问"能不能用 schema 或代码表达"。
- 身份文件（SOUL.md）仍然可以覆盖或补充措辞，但**不能取消这三条出口**——它们属于产品。
- 回放脚本成为提示词改动的唯一量尺；下一次改提示词，先跑三次再下结论。

## 不做

- **不做按 agent 配置的规则**：这是产品不变量，不是偏好。
- **不做更长的规则清单**：长清单会被当散文读；三条出口 + 五条约束已经是这个提示词的预算上限。
- **不用它替代代码校验**：槽位、授权、不可逆确认仍然在代码里；提示词只负责"模型愿意走这条路"。
