# ADR 0052: 池化调度与回交

- 状态: Accepted
- 日期: 2026-11-16
- 相关: ADR 0047（房间派单）、ADR 0048（能力卡/team_list）、ADR 0049（前台不变量）、ADR 0051（授权链）

## 背景

ADR 0047 的 `dispatch` 必须点名：`{agent, instruction}`。这在一个两人小组里够用，在事务所里暴露两个缺口：

1. **前台被迫当调度器。** 它得先 `team_list`、自己比较谁空闲、再点名——而"谁空闲"它看不到（team_list 只有能力卡），于是永远点同一个工人，其余排队。
2. **工人没有退路。** 接到不属于自己的活时只有两条路：硬做（超出能力）、或者把"我做不了"当成普通回复——可 dispatcher 当时没有活跃 run，那条消息只会静静躺在账本里，**没人被叫醒**。

## 决策

### 一、池化 dispatch：不点名 = 池子挑

`dispatch` 的 `agent` 变成可选；省略时调用 `pickAgent(capability?)`：

| 规则 | 理由 |
|---|---|
| 只考虑 `role === "worker"` 的启用 agent | 前台是人说话的地方，不是池子里的资源 |
| `capability` 对技能 id/描述做**大小写不敏感子串**匹配 | 与 ADR 0046 规则同一档粗糙度：子串写漏只是池子变宽，正则写错是静默全不中 |
| 排序：活跃 run 少 → 最近一次启动早 → id 字典序 | 空闲优先；同负载下摊开；完全并列时结果稳定，不会两次调用跳来跳去 |

**不做模型路由。** 派单在热路径上，模型路由等于把"工作室能否派活"绑到一次模型调用的可用性上——这正是 ADR 0048 把研判放在异步旁路的原因。池子选择是确定性的、可解释的，响应里回一句 `picked: "idle, picked from 2"` 让前台知道为什么是它。

负载判据是 `agentLoad()`：一次 GROUP BY 拿到每个 agent 的活跃 run 数与最近启动时间。注意它**跨会话**统计——一个工人在别的房间里忙着，这里也不再接活。

### 二、回交（handback）：工人把不属于自己的活退回来

新工具 `handback({reason, suggestion?})`：

- **只有被派发的 run 能用**：`authorization` 必须以 `dispatch:` 开头，收件人就是那个 dispatcher。人直接叫的活没有 dispatcher，`handback` 明确拒绝（"handback is for dispatched work only"）。
- **reason 必填**，suggestion 可选。没有理由的退回比硬做更难处理。
- 效果：在原会话里以工人身份、@ 给 dispatcher 发一条消息，`authorization = handback:<workerId>`，`parent_run_id = 工人的 run`。这**会唤醒 dispatcher**（正常路由），并在账本里留下"这件活被退回过"的事实。
- 框架文案明确写出"这件活仍然由你负责：换人或自己做，不要当作已完成"。

授权值多一个 `handback:<workerId>`。它不影响 ADR 0051 的通道模型——五条通道说的是**工作从哪来**，回交并不产生新工作，而是把既有工作退回去；它属于链条的一跳，所以和不变量一起扩成：

> `authorization` 以 `dispatch:` 或 `handback:` 开头 **⇔** `parent_run_id` 非空。

## 两份 schema 的漂移风险

产品工具 schema 在本仓库有两份手写副本：`manifest.ts`（Run 的清单，持久化并写进工作区）与 `dispatch.ts` 的 `PRODUCT_TOOLS`（MCP ListTools，**模型真正读的那份**）。历史上它们漂过（ADR 0033 §14 的 ask_question）。本次新增 `manifest-drift.test.ts`：两边工具集合、属性名、必填字段必须一致（`identity` 除外——那是 rail 用 `_meta` 注入的，不属于模型要填的东西）。

## 边界

- **不判"能力是否匹配任务"。** `capability` 是前台给的提示，池子只做子串过筛；真正的能力判断（模型研判）不在热路径上。
- **不做抢占。** 忙碌的工人不会被中途打断，池子只是绕开它。
- **回交不自动换人。** dispatcher 醒来后自己决定（再派、自己做、或问人）——自动转派会形成两个 agent 互相踢皮球而无人知晓。
- **不做跨房间池**。池子在"当前会话的成员"之外扩到全团队，但派单仍然会先把目标加进房间（ADR 0047 的成员语义不变）。

## 后果

- 前台可以说"这事谁有空"，不必先读名册再猜。
- 工人有了一条被记录、被唤醒、被审计的退路。
- 账本出现第五种行：`handback`（红点），说明"这条链上有人拒绝了"。
